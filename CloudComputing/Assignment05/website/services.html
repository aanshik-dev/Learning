Architecture & Orchestration

Managed Auto Scaling Platform

Comprehensive automation suite built using Python Boto3, AWS Auto Scaling, CloudWatch Metric Alarms, and Apache HTTP Server.

Step 01 • Ingestion
S3 Static Assets

Assets synced to /var/www/html during EC2 startup bootstrapping.

Step 02 • Identity
IMDSv2 Extraction

Token-secured EC2 metadata retrieves instance ID injected via sed.

Step 03 • Monitoring
CloudWatch Alarms

Monitors CPU load across the fleet over 2-minute evaluation periods.

Step 04 • Scaling
ASG Elastic Policy

Dynamic scale-up (+1) and scale-down (-1) maintaining 1 to 3 nodes.

Dynamic Elasticity

Configured with scale-out thresholds when average CPU exceeds 20%, ensuring zero performance degradation during high user traffic or spike events.

Self-Healing Fleet

Continuous EC2 system and instance status checks detect unhealthy instances immediately, automatically spinning up new healthy nodes.

IAM Security Isolation

Instance assumes aanshik-ec2-s3-role IAM Instance Profile for authenticated S3 access without storing secret keys on the filesystem.

Cool-Down Periods

Protects cluster stability by enforcing evaluation cooldowns, preventing thrashing (rapid scale-out followed by immediate scale-in).

Multi-AZ Fault Tolerance

Spans instances across availability zones in ap-south-1 (Mumbai) ensuring high availability even if a physical datacenter experiences outages.

Stateless Architecture

Nodes store zero local session state, allowing any incoming HTTP request to be served cleanly by whichever instance is provisioned by the ASG.
